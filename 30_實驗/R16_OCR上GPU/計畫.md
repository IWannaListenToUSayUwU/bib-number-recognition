# R16 OCR 上 GPU（研究流程第 5 階段：提速）

開始：2026-11-23（使用者要求「用 GPU 跑一下即時怎麼樣」）。

## ① 問題
- 即時是專題目標 3。現況（R14，GLOBAL_v3_0，沒開遊戲）：C 段 60 秒影片抽取 481 秒、D 段 583 秒，**比即時慢 8～10 倍**。
- OCR 在 CPU 上（onnxruntime 只有 CPU 版），佔抽取時間約 95%（R13）。

## ② 假設
OCR 改用 GPU（onnxruntime-gpu），每次 OCR 時間降到 1/3 以下，而讀數幾乎不變。

## 環境（不動 bibread）
- 安裝 `onnxruntime-gpu==1.26.0`（PyPI，226.5 MB）到 **`C:\Users\ShiLaCow\bibread_ortgpu\ort126`**（`pip install --no-deps --target`），bibread 環境本身沒改。
  用法：把這個資料夾放在 `sys.path` 最前面（或設 `PYTHONPATH`），並且**先 `import torch`** 再 import onnxruntime（借用 torch 2.6 附的 CUDA 12.4／cuDNN 9.1 DLL）。
- 為什麼是 1.26：1.27 起 onnxruntime-gpu 改用 CUDA 13，torch 附的是 CUDA 12；1.26 是最後一個 CUDA 12 版本，不用另外下載 CUDA／cuDNN。
- 刪除＝直接刪那個資料夾。

## ③ 事前量測（2026-11-23 晚，`事前量測\ocr_gpu_bench.py`）
從 tpe_C_600 每 0.5 秒取一格、用 extract8 的軀幹裁切，得 699 張圖；同一批圖用 4 種方式各讀一次。
**量測時使用者在玩 VALORANT（約佔 CPU 31%、GPU 54%）→ 速度數字只能看相對大小，不可當正式結果。** 讀數比對不受影響。

| 跑法 | 每張（毫秒） | 讀數和原本相同 |
|---|---|---|
| 原本 CPU（ORT 1.31.1，8 執行緒） | 426～472 | — |
| ORT 1.26 CPU | 711（其中 det 372、rec 104） | 文字＋分數 699/699 |
| ORT 1.26 GPU | 148～192（其中 det 95、rec 38） | 文字 688/699、文字＋分數 456/699（分數差最大 0.076） |
| ORT 1.26 GPU、cuDNN 搜尋改 HEURISTIC | 177～214 | 同上 |

- **版本不影響讀數**（1.26 和 1.31 在 CPU 上完全相同）；**差異來自 GPU 運算**（cuDNN 浮點誤差）：11/699 張的文字改變，都是邊緣讀數，有變好也有變壞
  （例：`0144`→`01434`、`0418`→`041`、`313`→讀不到）。
- 同時間比較 GPU 約快 3～3.7 倍。HEURISTIC 沒有比較快 → 維持 RapidOCR 預設。
- GPU 每張還有約 60 毫秒花在 det／rec 以外（前後處理在 CPU 上，遊戲也在搶 CPU）。

## 粗估（未驗證）
沒開遊戲時正式流程每次 OCR 約 0.21 秒（R14：C+D 1064 秒／5024 次），GPU 快 3 倍 → C 段約 150～200 秒／60 秒影片，**仍比即時慢 2.5～3 倍**。
光把 OCR 搬上 GPU 不夠；之後可能還要：一次把同一格的多個人一起送進 GPU（batch）、縮小 det 輸入（R13 E5 掉分的原因已知）、更強的顯卡。
