# R08 換人偵測（調嚴衣服顏色切換）總結

日期：2026-11-18～19　執行：使用者電腦 GPU（執行時同時開著遊戲，耗時數字不可比）
評分：`20_測試基準\score.py`（C、D；±2 秒；號碼完全一致）

## 改了什麼
只改「何時把一條軌跡切成兩個人」，挑圖（bins，12 張）與投票（aggregate3）和 R07 v2.3b 完全相同。
- 舊：整塊軀幹 色相×飽和度 直方圖，單一幀距離 > 0.45 才切
- 新（`10_程式\src\feat6.py`、`extract6.py`）：上衣只取左右兩側（避開號碼布）＋褲子分開算；HSV 加亮度格；最近 3 幀平均 vs 軌跡外觀，> 門檻就切，切點往回放

## 事前量測（雲端，C、D 各 60 秒，YOLO+ByteTrack 不做 OCR）
「同一人相隔約 0.5 秒」vs「同一時間站得近的兩個不同人」：
| 特徵 | 單幀 AUC (C/D) | 3 幀平均 AUC (C/D) |
|---|---|---|
| 舊（整塊軀幹） | 0.911 / 0.862 | 0.965 / 0.944 |
| 新（上衣兩側+褲子平均） | 0.948 / 0.918 | 0.979 / 0.964 |
舊門檻 0.45 單幀只抓到 34% / 39% 的「不同人」。

## 結果

## 結論
- 差異只有 ±1～2 個號碼（共 108 個），在雜訊範圍內：**調嚴顏色切換沒有帶來可確認的提升**。
- 「混人軌跡」幾乎沒降（55 → 52）。代表混人的主因可能不是「衣服不同卻沒切開」：
  軀幹裁切左右各外擴 8%，擁擠時旁邊跑者的號碼也會被 OCR 讀到，這也會被算成混人。下一步應先查這個。
- 新方法 OCR 次數較多（D：2569 vs 2486），速度不划算。暫不採用，預設維持 v2.3b / v2.2。

## 更正
專案導覽.md 之前寫 v2.3b = 0.917 是錯的：用同一支評分程式重算，v2.3b（bins + aggregate3）= 0.900；
0.917 是 v2.2（R06）與 bins + 逐字投票（aggregate5）的分數。
