## 目前能做到什麼
- 從比賽影片中找出每個跑者、讀出號碼布，並算出他**通過計時線的時間**（畫面上自訂的虛擬線）。
- 有入鏡的比賽時鐘時，過線時間可以換成**槍聲時間**（終點線機位：和官方成績的差有 90% 落在一個寬 1 秒的視窗內——官方只到整秒，代表系統誤差多半 < 0.3 秒）。

**成績單**（`20_測試基準/成績單.md`，`python 20_測試基準/scorecard.py` 產生；主要指標＝號碼和過線時間都對的比例）：

| 版本 | 臺北馬轉角 C+D（人工答案，122 人） | 臺北馬終點 tpe2（官方名單，160 人） | 新屋終點測試段（官方名單，92 人） |
|---|---|---|---|
| v3.0 | 0.762 [0.68, 0.83] | 0.225 [0.17, 0.30]，錯誤輸出 3 | 0 |
| **v3.1**（定版） | 0.762（完全相同） | 0.225（完全相同） | **0.391 [0.30, 0.49]，輸出 36 個全對** |

- 時間誤差中位數：轉角 0.06 秒、終點約 0.36 秒（官方只到整秒）、新屋 0.07 秒。
- 終點、新屋的分母是全部完賽者（包含號碼本來就看不到的人），比人工答案嚴格；人眼看得出的上限尚未量測。三個測試集都已經用過，不是保留卷。
- 終點線機位讀號碼仍弱：影片過曝／低畫質、號碼對比低，跑者靠近時每張畫面也只有約 14% 讀對（R13、R17 已確認不是裁切或前處理的問題）。
- 速度：60 秒片段要 8～20 分鐘（OCR 在 CPU 上）；OCR 改 GPU 每張約快 3 倍（R16 初測），仍離即時很遠。
- v3.1＝v3.0＋R17 的兩個通用修正（追蹤／讀字門檻分開、號碼前多印字的讀數取名單上唯一的 5 碼）；過線距離、定案等待改由機位層設定。2026-11-24 定版。

## 新 demo 怎麼做的
- 系統：v2.2（每秒 16 格）抽取的結果（`30_實驗\R12_第二機位\out\FROZEN_CONFIG_v2_2\`）＋三層設定 `GLOBAL_v3_0`（候選）的號碼定案規則
  （號碼名單＋共識解碼＋號碼布顏色）和機位計時線。
- 指令（在專案根目錄，不需要 GPU，每支約 1 分鐘）：
  ```
  python 10_程式/src/render_crossing_demo.py GLOBAL_v3_0 tpe_C_600 30_實驗/R12_第二機位/out/FROZEN_CONFIG_v2_2/tpe_C_600/raw.jsonl 40_成果/過線計時demo/過線計時_轉角機位_tpe_C_600.mp4
  python 10_程式/src/render_crossing_demo.py GLOBAL_v3_0 tpe2_B_4200 30_實驗/R12_第二機位/out/FROZEN_CONFIG_v2_2/tpe2_B_4200/raw.jsonl 40_成果/過線計時demo/過線計時_終點線機位_tpe2_B_4200.mp4 --gun 14524.067
  ```
  （`--gun`＝片段第 0 秒的槍聲時間，來自畫面時鐘，見 `30_實驗\R12_第二機位\時鐘對照.json`。）
- 影片素材是別人上傳的 YouTube 比賽影片片段，只供專題展示。

- 新屋 demo 指令（不在 MANIFEST 的長影片）：
  ```
  python 10_程式/src/render_crossing_demo.py GLOBAL_v3_1 xinwu_900 30_實驗/R17_最終魔王/out/r17e_test/seg_0900/raw.jsonl 40_成果/過線計時demo/過線計時_新屋終點_900.mp4 --video "00_原始素材/最終魔王/2026 10 04 2026新屋魚米之鄉馬拉松終點 GP020205.mp4" --race xinwu2026 --camera xinwu_finish --t0 900 --dur 60 --gun 26554.73
  ```
  （`--gun`＝影片第 900 秒的當天時刻 07:22:34.73，由官方成績和大會起跑時間推得，見 R17總結.md。）
